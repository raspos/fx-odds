# FX ODDS 갱신 체크리스트

평일 08:40·18:40 KST 자동 갱신(GitHub Actions `daily`) 뒤 사람이 확인한다. GitHub 스케줄은 몇 시간 늦거나 건너뛸 수 있으므로(2026-10-27 18:40 실행이 6시간 늦게 시작됨) 시각이 아니라 **'갱신' 시각과 자료 기준일**로 판단한다. 수시로 직접 돌릴 때는 Actions → `daily` → **Run workflow**(Re-run 아님).

## A. 자동 갱신 확인 (3분)

1. **실행 성공** — Actions 맨 위 `daily`가 초록인지. 실패면 실패한 단계 이름과 마지막 오류 한 줄을 본다(코드 수정 푸시는 약 2~5분 빠른 배포, 정기·수동 실행은 약 5~7분 전체 수집·분석).
2. **갱신 시각과 경고** — 화면 상단 '갱신'(자료 수집이 마지막으로 끝난 시각)이 평일 기준 하루 안인지. 노란 경고(`자료 N일 전`, `최근 수집 실패 … 원인`)가 없는지.
   - `원인: 인증키 오류(INFO-100)` → GitHub 시크릿 `ECOS_API_KEY`를 키 문자열만 다시 저장(공백·따옴표·이름 없이)
   - `원인: 네트워크 오류` → 보통 일시적. 다음 실행까지 기다려 보고 반복되면 해당 출처 차단 여부 확인
3. **자료 기준일 (meta.json 의 sources)**
   - 한국은행 ECOS 원/달러: 전 영업일(당일 오후 이후면 당일)
   - Yahoo 일봉(환율·금리·VIX·유가·코스피): 전 영업일. 4일 넘으면 경고
   - ECOS 국제수지(월): 두 달 전 말일(발표 지연이 정상)
   - ECOS 고가·저가(731Y003): 전 영업일까지(이용 가능일 = 관측일 + 1영업일)
4. **실시간 예측 기록** — `live_forecasts.csv` 줄이 오늘 기준일로 늘었는지(하루 한 번, 덮어쓰기·중복 없음). 목표일이 지난 기록은 예측 성적표 맨 위 '실시간 예측 성적표'에서 채점되는지.
5. **시장 호가** — 화면의 '참고 시장 호가' 시각이 장중이면 최근 40분 안, 아니면 '마지막 호가'로 표시되는지(호가 전용 스케줄은 자주 건너뛰므로 전체 실행 때 갱신되면 정상).

## B. 사람이 보는 것

6. **뉴스·AI**
   - 압력·뉴스 탭 '수집/판단/유보/분류 불가/AI 보조' 건수가 어제와 비슷한 규모인지(수집이 0건이면 네이버 키·한도 확인).
   - 규칙·AI 방향 일치 건수의 '반대'가 급증하지 않았는지, AI 판단 카드에 환율과 무관한 기사가 섞이지 않았는지.
   - 오분류가 반복되면 `py/news.py`의 규칙(RULES)을 고친다(예: '긴장 완화'를 약세로 본 사례).
   - AI 사용량 `data/ai_usage.csv`가 갑자기 커지지 않았는지(실행당 상한이 있으나 확인).
7. **증권사·기관 전망 표**
   - 같은 기관이 한 줄에 여러 시점을 묶어 보이지 않는지(기관 × 목표 시점 분리), 컨센서스가 같은 시점끼리만 기관 2곳 이상일 때만 나오는지.
   - 원문을 확인한 전망은 `data/reports_manual.yaml`에 `target_key`(예: `2026-END`, `2027-Q1`, `2027-AVG`)와 함께 `verify: false`로 추가. 원문을 못 봤으면 넣지 않는다.
   - 새 IB·증권사 이름이 표에 다르게 표기되면 `py/reports.py`의 CANON에 추가.
8. **FPI·FXVI 상태** — FPI 자료 충족률이 100%인지(월별 국제수지는 두 달 지연). FXVI가 '산출 보류'면 같은 관측 구간 252거래일이 부족한 것인지 확인.
9. **관측 범위 변화 점검** — 외환시장 거래시간·고저가 집계 기준이 바뀌었다는 공지가 있으면 `py/vol.py`의 `BREAKS`에 날짜를 추가하고 단절 검정 결과를 확인한다.

## C. 배포 뒤 대조

10. **외부 사이트 새로고침(Ctrl+F5) 후 숫자 대조** — 상단 4칸(원/달러, 7일·30일 80% 범위, 뉴스 압력지수)과 메인 3카드(확률·압력·변동성)가 같은 기준일인지.
    - 원/달러: ECOS 731Y001 매매기준율과 일치(전 영업일 거래 반영값이라 시장 호가와 몇 원 다를 수 있음)
    - 변동성 탭: 최신 완결 세션 고가·저가가 ECOS 731Y003과 같은지
11. **구현 상태 표** — 방법론 탭 '구현 상태'가 코드가 만든 `features.json` 값과 맞는지(자동 생성이므로 어긋나면 빌드 오류).
12. **과거 날짜 선택 시험** — 날짜를 하나 골라 세 카드가 모두 그 날짜 값이거나 '당시 자료 없음'인지(최신 값이 섞이면 안 됨), 변동성 탭이 안내 문구만 보이는지.
13. **화면 이상** — 빈 칸, 'null'/'NaN', 가로 넘침(모바일 폭 320px), 콘솔 오류.

## D. 주기 점검

14. **월 1회** — 시크릿(ECOS·네이버·OpenAI) 유효성, GitHub Pages 배포 정상, 저장소 용량(`data/fx.sqlite`).
15. **분기 1회** — 실시간 예측 성적표 누적 표본(평가 30건 이상이면 포함률 해석 시작), 백테스트(`daily` 전체 실행이 갱신)와 비교.
16. **모형·규칙을 바꾼 날** — `model_version`·버전을 올리고 방법론 변경 이력에 한 줄 추가, 백테스트 캐시 키(`bt2-`)를 올려 예전 캐시가 쓰이지 않게 한다.

## 자주 겪는 일

- 전체 실행이 빠졌거나 늦다 → Run workflow로 수동 실행.
- 예전 실행을 Re-run으로 돌렸다 → 예전 코드로 돌아 실패한다. 항상 새 실행.
- 호가가 계속 '마지막 호가' → 정상일 수 있음(장외 시간·스케줄 건너뜀). 급하면 `quote` 워크플로 수동 실행.
- 'ECOS 수집 실패' 경고가 계속 → 시크릿 값 확인 후 새 실행(경고는 직전 실행 기록).
- 푸시가 거부됨 → `git pull --rebase` 후 다시 푸시(봇의 데이터 커밋과 충돌).
